Did the change make the assistant better or worse?

Pick two versions. The harness scores both on the same labelled cases, puts error bars on every number, tests the difference, and says ship or block. Everything below is computed in your browser by the code in src/.

Try to break it

1Headline metrics

Intent is one of seven labels. Each bar is a 95% bootstrap interval (2,000 resamples, fixed seed): if two bars overlap a lot, the difference may be noise.

2Is the difference real?

3Slices

An average can hide a group that got worse. A slice is flagged when it drops by more than the gate allows. Slices overlap: an Albanian email counts in both rows.

4Where the errors go

Rows are the true intent, columns what the version said. Off-diagonal cells in colour are mistakes.

5Urgency calibration

When a version says it is 90% sure of an urgency, it should be right about 90% of the time. The gap, averaged over cases, is the expected calibration error.

6The judge, measured against people

A rule-based judge scores every drafted reply. A judge is an instrument, so it is checked against replies that a person rated (written for this demo, 4 or 5 out of 5 means acceptable). Kappa is agreement beyond chance.

7Flaky cases

A deterministic stand-in never changes its mind, so seeded sampling noise is added to its scores to mimic a model run at a temperature above zero. Run the candidate ten times: cases that do not give the same answer every time are the ones a single run cannot be trusted on.

8Case inspector

Click a case to see the message, the gold labels, both outputs and the judge's reasons.

Method: the core in src/ is plain ES modules that this page imports unchanged; the same code runs npm test, the command-line gate and CI. The candidates are hand-written rule sets standing in for model versions, and the human ratings were written for the demo, so none of these numbers say anything about a real model.
